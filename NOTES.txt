Process 

The baseline (tage192) is the reference data. tage192 is typically run
then the entries are run to generate the comparison data.

I normally then write protect the results before I begin iterating on
any new designs.

./results is where the execution results are placed. For merges and the
other post processing I put them in ./summary.

The make file targets handle this process. Change as needed.


1) Clean models

	make clean

2) Build models

	make all

3) Optional clear out all results

	make clean_baseline
	make clean_entries

4) Optional: Run the base line predictor across all traces
   Or keep the previous run. Required if clean_baseline. This
   make target write protects the baseline directory results/tage192

	make run_baseline

5) Run the target implementations across the desired traces. Edit
	R_ENTRIES and R_GROUPS or add from command line, comma sep arg. This
  also write protects the results

	make run_entries

A) Merge and summarize available results compare to tage192, output
   two CSV. summary/group_results.csv and summary/group_summary.csv

	make summary

B) Emit simple summary tables to console

	make simple_tables

C) Emit simple summary tables to console

	make simple_tables


For A,B,C no ordering is required.

Comments about the workload characteristics

  These are useful when explaining why a predictor helps hurts certain workloads

  When comparing predictors quote density 

    “This workload has 2× the branch density of fp, so absolute gains differ.”

  When CycWpPKI ≠ BrMisPKI
    look at indirect density

  When conditional density is low
    stop tuning TAGE and look at:
      fetch policy
      return handling
      BTB structure
